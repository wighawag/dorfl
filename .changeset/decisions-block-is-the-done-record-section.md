The build agent's `## Decisions` block is now explicitly the done-record section, and the runner is more forgiving when an agent gets it wrong. The prompt (`CLAIM-PROTOCOL.md`), `WORK-CONTRACT.md` and the task template now say to end the final report with the block, written for a reader of `work/tasks/done/<slug>.md` rather than as a message to the reviewer, with an example and the relative link form (`../../../docs/adr/...`, `../../notes/...`). They also say that an older task body asking to "record decisions durably and link them from the done record" is satisfied by this block. When the runner transcribes the block, it now drops obvious reviewer-addressed lines ("I could not add the ## Decisions section myself", "Please append this line to work/tasks/done/...", "Note to the reviewer: ..."); a request or an inability only counts when the line names the record itself, and quoted text is ignored, so a decision quoting a user-facing "please add ..." message is kept and prints a warning listing them. A payload given inline after "please append ...:" is kept. When a build adds a decisions note under `work/notes/observations/` (`decisions-<slug>.md` or `<slug>-decisions.md`, optionally dated) that the done record does not reference, the runner now links it from the record's `## Decisions` section (creating one if needed) in the same completion commit, and warns that the report's block is the intended channel. A repo whose `work/protocol/` copy still carries the old wording should run `dorfl sync`.
