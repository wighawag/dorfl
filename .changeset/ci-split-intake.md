The CI split where the agent job holds no write token now covers `intake`: `intake <N> --phase lock|agent|apply` (with `--handoff-out` / `--handoff-in` and `--agent-result`, the lock job's outputs read back from `DORFL_LOCK_OUTPUTS`). The lock phase reads the issue, its thread and its labels, takes the `processing` label, runs the deterministic triage (a skip publishes `needsAgent: false`), and publishes the origin trust (from the event's `comment.author_association`, else `issue.author_association`, unless `--origin-trust` is given), the document mode (`intakeIntegration ?? integration` from `dorfl.json` at the arbiter's `main`) and every comment id it read. The agent phase shows the decision agent only those comments (a comment posted after the lock is neither read nor marked seen), runs the decision and the lone-task review, and hands over only the verdict fields the intent table allows. The apply phase never takes a document from the agent job: it recomputes the slug from the title (checked by `slug-safety.ts`), the placement, the stamp and the mode, re-renders the document with the title quoted, re-parses it to prove `origin`, `originTrust`, `slug` and `issue` are the trusted values, then comments, closes or integrates, and always removes the label; an agent job that did not succeed, a rejected handoff, or a triage skip only removes the label. Two supporting changes: the `seenCommentIds` lock output now also accepts GitHub comment node ids (`IC_kw...`, what `gh issue view --json comments` reports), and the intake triage no longer counts an intake comment id recorded in `seen=` as a deleted comment. The slug of a CI-emitted task or spec is derived from its title, so the agent's own slug suggestion is not used there. No generated workflow uses `--phase` yet, and nothing changes without it.
