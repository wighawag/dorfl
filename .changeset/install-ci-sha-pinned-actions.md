'dorfl': patch

Every third-party GitHub Action `dorfl install-ci` generates is now pinned to a full commit SHA, and regenerating keeps the pins your repository already has. Re-run `dorfl install-ci` after upgrading to pick this up.

**SHA pins in the Dependabot format.** The generated workflows and the composite `dorfl-setup` action referenced `actions/checkout@v5`, `actions/setup-node@v5` and (workspace mode) `pnpm/action-setup@v5`. A tag can be moved by whoever controls the action's repository, and these jobs hold `contents: write` and a provider API key. They are now emitted as `owner/repo@<40-hex-sha> # vX.Y.Z` from one table (`install-ci-action-pins.ts`), which is the format Dependabot writes, so its `github-actions` updates keep them current (list `/.github/actions/*` in `directories` to reach the composite action). The defaults move to the current majors: `actions/checkout` v7.0.1 (blocks checking out fork pull-request code under `pull_request_target` / `workflow_run`), `actions/setup-node` v7.0.0 and `pnpm/action-setup` v6.1.0. The inputs dorfl passes are unchanged, and `package-manager-cache: false` still applies (its comment now describes the v6+ behaviour). `docs/ci/advance-loop.yml.template` and the project-setup example in `docs/ci/README.md` use the same pins.

**Your pins survive regeneration.** When `install-ci` rewrites a file under `.github/` that already pins an action to a full SHA, it keeps that reference and its trailing comment instead of dorfl's default. Actions are matched by `owner/repo` (plus the path for an action in a subdirectory), not by position; if the file pins one action to several SHAs, the highest `# vX.Y.Z` wins. An existing tag is not a pin, so it is replaced by dorfl's SHA, and a SHA is never replaced by a tag. This also covers the steps spliced in from a `projectSetup` snippet, so a Dependabot bump in the composite action is not reverted by a stale pin in your install-ci config. `--fake` previews read the existing pins from `.github/` too.

A new test parses every generated workflow and composite action, for every config shape, and fails on any `uses:` other than a local `./` reference that is not `@` followed by exactly 40 lowercase hex characters.
