The CI split of the build path now acts on the agent job's result before it reads anything the agent job left behind. The apply phase takes `needs.agent.result` through the new hidden, CI-only `--agent-result` (required with `--phase apply`): only `success` reads the handoff. A `failure`, or a `skipped` agent job when the lock phase said the item needs an agent, surfaces the item to needs-attention and releases the lock. Because GitHub reports a timed-out job as `cancelled`, a `cancelled` agent job is looked up in the Actions API with the job's own `GITHUB_TOKEN` (never `DORFL_GH_TOKEN`): a GitHub timeout annotation on any page, or a run time within a minute of the agent timeout, surfaces the item, a real cancel only releases the lock, and anything that cannot be read surfaces it. Annotation text is only matched, never printed. The lock phase now publishes `agentTimeoutMinutes` (`agentDeadlineMinutes + checkpointHeadroomMinutes` from the config at the base), which the apply phase also accepts as `--agent-timeout-minutes`. A "Re-run failed jobs" of a finished run writes nothing and says to start a new run; a "Re-run all jobs" attempt takes a fresh lock and names its artifact with the new attempt. Nothing changes without `--phase`.
