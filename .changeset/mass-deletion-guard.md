Builds now catch an agent that accidentally guts a pre-existing file. After the build agent finishes and before the acceptance gate, dorfl diffs the work against where it started. When a pre-existing text file loses more than 150 lines net, or more than 40% of its lines (and at least 20), the agent gets one follow-up turn in the same session listing each file: restore it and redo the change as a targeted edit if the content was lost by accident, or leave it if the removal is part of the task, including content deliberately moved elsewhere (a file split, an extraction), which the agent is told not to restore. Anything still flagged after that turn is appended to the PR body under "Large deletions (runner check)" so the reviewer sees it at once. The check is advisory and never fails a build. It runs on `do`, `do --remote`, the CI build phase and `run`. It is on by default; turn it off with `massDeletionGuard: false` in `dorfl.json` (or `DORFL_MASS_DELETION_GUARD=false`), and tune it with `massDeletionLines` and `massDeletionRatio`. A single task planned as a big refactor can opt out with `massDeletionGuard: false` in its frontmatter. The worker prompt also now asks the agent to edit large existing files with targeted edits instead of rewriting them whole. See the ADR `mass-deletion-guard-asks-the-agent-once-then-tells-the-reviewer`.
