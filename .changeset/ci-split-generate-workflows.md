`dorfl install-ci` now generates the split CI workflows, where the agent job holds no write token. Every CI item runs as three jobs in `dorfl-item.yml`: `lock` (write token, no agent: takes the locks at the arbiter's current `main`), `agent` (read-only token, `persist-credentials: false`, LFS on: runs the agents and uploads the handoff) and `apply` (write token, no agent: validates the handoff and does every write, `if: always()`). `advance-lifecycle.yml` no longer runs agents or a matrix: `enumerate` (`contents: read`) lists the items and a `dispatch` job (`actions: write` only, no checkout, no setup) starts one `dorfl-item-dispatch.yml` run per item, spread over `maxParallel` concurrency slots with `queue: max`, skipping an item whose `dorfl-item <item>` run is not completed yet and forwarding `integrationMode` and the four gate overrides. `intake.yml` calls `dorfl-item.yml` with `item: issue:<N>`. Every generated workflow grants nothing at workflow level (`permissions: {}`), and each job its own scopes. A new writer-role setup action (`.github/actions/dorfl-setup-writer`: Node and dorfl only, installed from `$RUNNER_TEMP` with `--ignore-scripts`, no harness, no provider key, no project-setup hook, no cache) serves the lock, apply, `enumerate`, `reap-merged-branches` and `close-job` jobs. `actions/upload-artifact` (v7.0.1) and `actions/download-artifact` (v8.0.1) are pinned to full commit SHAs. The `advance-lifecycle` push trigger is pinned to `main`, and the template comments no longer claim that a lost CAS re-runs the gate. A workflow guard test checks every generated file and this repository's own `.github/`, which is regenerated in the same change.
