The CI split (`--phase`) now carries new Git LFS objects from the agent job to the apply job. The agent phase scans the blobs its new commits add or change for LFS pointers (a blob that parses as a pointer counts, whatever `.gitattributes` says) and copies each referenced object from its local store into the handoff as `lfs/<oid>`. The apply phase checks every pointer with a strict spec v1 parser and rejects the whole handoff for a blob that looks like a pointer but is malformed, a missing object, an object whose size or sha256 hash does not match its pointer, an object no pointer references, or objects over the LFS size limit. It then pushes the objects with `git lfs push --object-id` from its checkout of the trusted base, before any ref of any outcome (the land, a needs-attention or deadline-checkpoint WIP branch, a STOP, an agent failure), so a branch never lands pointing at a missing object. Accepted consequence: a text file that happens to parse as an LFS pointer (a test fixture, say) is treated as one, so its object must be present. The agent job's `lfs: true` checkout and `git lfs install --local` come with the generated workflows, which do not use `--phase` yet. Nothing changes without `--phase`.
