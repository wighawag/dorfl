The CI split where the agent job holds no write token now covers tasking: `do spec:<slug>` and `advance spec:<slug>` accept `--phase lock|agent|apply` (with `--handoff-out` / `--handoff-in`, `--agent-result` and `--agent-timeout-minutes`, the lock job's outputs read back from `DORFL_LOCK_OUTPUTS`). The lock phase checks the spec at the arbiter's `main` (it must rest in `work/specs/ready/` and pass the agent tasking gate; `advance` also classifies it on the `task-spec` rung), takes the tasking lock and publishes the trusted facts. The agent phase runs the tasker, its review rounds and the one-round task-set review (which the single-process path runs inside the integrate) on a branch cut from the lock job's base, writes nothing to the arbiter, and hands over `tasking-land` (the candidate tasks, the review verdict and prose, the trimmed spec body) or `tasking-surface` (a review block, an unclear decomposition, a failed review leg); a tasker failure writes no handoff and fails the job. The apply phase never takes a bundle: it re-commits only checked files on a fresh branch cut from the base. Each candidate must be a new `work/tasks/backlog/<safe-slug>.md` (an edit to a staged task already on the base is rejected), its frontmatter must parse, `humanOnly` / `needsAnswers` must read as booleans (at most once each), and its `origin` / `originTrust` lines are replaced by exactly one line each carrying the spec's stamp, then re-parsed; so a candidate that repeats `originTrust: trusted`, or leaves its frontmatter fence unclosed, can no longer carry a trusted stamp past the check. The trimmed spec body must keep `humanOnly`, `needsAnswers`, `taskedAfter`, `issue`, `origin`, `originTrust` and `slug` exactly as they are at the base and keep the Problem Statement, Solution and User Stories headings the base has. It then integrates the tasks and the spec move with the review off (the review prose is still posted on the PR), or saves the candidates on `work/spec-<slug>`, closes a stale PR in propose mode and surfaces the spec. A rejected handoff, a failed or timed-out agent job surfaces the spec; a real cancel only releases the lock; every release is leased on the lock job's lock. In the phase split the apply job commits only the candidate tasks and the spec: other files the tasker agent wrote, and the task-set review's non-blocking-findings observation, are not carried. No generated workflow uses `--phase` yet, and nothing changes without it.
