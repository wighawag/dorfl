Correct three things in the `one-shot` skill that 0.14.0 shipped: it is now COMMIT-ONLY (no remote, no PRs), its bootstrap is keyed on the CONTRACT being missing rather than the project being absent, and it explicitly declines `setup` Phase B.

**Commit-only.** The skill commits locally and never pushes, and pushing has moved into the stop bar beside spending money and deploying. The human's `git push` becomes the last gate: publishing is an external consequence, which is exactly the class an unattended agent must not decide on its own, and keeping the whole run local makes the worst case of a bad night a `git reset` rather than a broadcast. This DELETES rather than merely forbids: there is no integration mode to pick at kickoff, no `gh`/PR/propose path, no remote arbiter, and no `ls-remote` precondition, and worktrees branch off local `main`. The land primitive is deliberately KEPT, because `main` still moves as each task's siblings land onto it; what the local-only shape removes is the fetch and the lost-CAS retry, not the rebase-and-re-verify invariant.

**Bootstrap is keyed on the contract, not on emptiness.** Phase 0 was gated on "the project does not exist yet", but what it establishes is the contract plus a real gate, and both are independent of whether code exists (a five-year-old repo can lack both; a fresh template scaffold can already have the gate). An existing-but-unadopted repo therefore fell through a hole: Phase 0 was skipped and the loop then read protocol docs that were not there. It now triggers on `work/protocol/` absent OR `verify` not real, with per-step skips for whatever is already true. That surfaced the missing existing-repo half of the gate step: discover the gate from the repo's own tooling and RUN it once before dispatching anything, and treat an already-red baseline as a STOP rather than a starting point, because building on it makes every later "the gate is red" signal uninterpretable (you cannot separate your own breakage from the inherited kind).

**`setup` Phase B is declined by design, and said out loud.** Converting an existing repo's trackers, design docs and code onto the contract is the one part of adoption that cannot be one-shot: its central discipline is that an ADR is written if and only if a human supplies the WHY, and with no human the rule is explicit that you write nothing. An unattended agent that converts anyway produces precisely the fabricated rationale that rule exists to prevent, and a fabricated ADR corrupts the decision record silently, which is worse than an empty one. The skill now adopts the Phase A skeleton, leaves legacy material where it is, reports the gap, and recommends an interactive `setup`. The neighbouring ADR rule is sharpened so the two cannot be misread one line apart: record the decisions YOU made, never one you found in the code, the boundary being whose decision it was.

Also adds the precondition that the protocol docs must be reachable, naming the hidden coupling that `one-shot` installed WITHOUT `setup` beside it cannot bootstrap, because the docs are copied from `setup`'s own `protocol/` folder.
