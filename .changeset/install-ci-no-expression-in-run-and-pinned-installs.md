'dorfl': patch

Harden every workflow `dorfl install-ci` generates against GitHub Actions script injection and unpinned installs. Consumers are told not to hand-edit the generated files, so re-run `dorfl install-ci` after upgrading to pick this up.

**No `${{ }}` inside a `run:` script, anywhere.** An expression in `run:` is substituted as text before the shell starts, so its value becomes part of the script. The advance matrix legs ran `dorfl advance "${{ matrix.item }}"`, and an item id is a slug read from `work/` (frontmatter `slug:` or the file name) that `intake` drafted from issue content through `paramCase`, which kept `$(`, backticks, `"` and `;` (see the slug-safety changeset for that half of the fix). The item now reaches the shell through the step `env:` as `WORK_ITEM` and is read as `"${WORK_ITEM}"`. The same treatment applies to the three dispatch gate-override steps (which also refuse a value containing a line break, so a future free-text input cannot append its own `$GITHUB_ENV` lines) and to the intake step's issue number and policy flags. Behaviour is unchanged for every legal value. A new test parses every generated file as YAML and fails if any `run:` value contains `${{`, and the structural validators gained matching invariants.

**Pinned global installs.** The composite `dorfl-setup` action now installs `dorfl@<the version that generated it>` instead of `dorfl`, so CI runs the same CLI that wrote its workflows, and the `pi` harness at `@earendil-works/pi-coding-agent@0.80.6` (the `PI_HARNESS_VERSION` this release declares) instead of an unpinned `@mariozechner/pi-coding-agent`. That old name is deprecated upstream and frozen at 0.73.1; the new package ships the same `pi` binary and reads the same `~/.pi/agent/` config. 0.80.6 is the version dorfl is exercised against day to day, not the newest release, and it needs Node >= 22.19.0, which the action's `node-version: '22'` resolves to. Both run in jobs that hold `contents: write` and a provider key.

**`persist-credentials: false` on the read-only jobs, only when provably safe.** `install-ci` now asks the provider for the repository's visibility. On a public repository the `verify` and `close-job` checkouts drop the persisted token (both jobs have `contents: read`, and public reads need no token). Private, internal or unknown visibility keeps today's checkout, because a `git fetch` in the project's gate or project-setup hook needs the token there.

**`--ignore-scripts` in workspace mode.** The self-hosting build installs with `pnpm install --ignore-scripts`; the build is explicit, so nothing depended on an install-time script. Consumer installs live in the project-setup hook, which dorfl does not write: `docs/ci/README.md` now shows `--ignore-scripts` in the hook example and explains the tradeoff.
