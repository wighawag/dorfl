'dorfl': minor
---

Merge questions now actually happen. A new no-agent command, `dorfl surface-merge-questions`, fetches the arbiter and asks a merge question (a `kind: merge` sidecar entry, answered `merge | hold | drop`) for every unmerged `work/task-<slug>` branch that has no open PR (on GitHub an open PR already is the land decision), whose task rests in `tasks/ready/` or `tasks/backlog/`, whose lock is free or kept by its finished propose build, and whose tip carries the done-move; it then publishes the questions to `main`. The generated `advance-lifecycle` workflow runs it as a new `surface-merge-questions` job (re-run `install-ci` to pick it up), and the bare laptop `dorfl advance` runs the same pass before it selects. A propose build that keeps its lock until the PR merges now stamps it `keptFor: propose-pr`, and an answered `merge` on such an item takes that lock over and lands the branch (rebase, re-verify on the rebased tip, advance) with no manual `release-lock`, on the laptop and in the CI lock, agent and apply jobs alike; a lock held without the marker (a live build) is never taken over. The in-place `advance` now threads `workspacesDir`, `prepare`, `verify` and `strictMergeApproval` to the answered-merge action, which it previously refused as a usage error. `mergeQuestions` is now `off | ask` (default `ask`): the never-implemented `auto` value and the never-read `advance --merge-questions` flag are removed, and `DORFL_MERGE_QUESTIONS=auto` is now rejected.
