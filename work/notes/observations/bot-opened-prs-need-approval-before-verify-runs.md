Found in the CI sandbox `wighawag/dorfl-ci-sandbox` (private, dorfl `main@e972795d` installed from a tarball, workflows generated by `install-ci`), while exercising the split CI workflows end to end.

Every PR opened by the generated workflows under `GITHUB_TOKEN` (intake PR #6, build PRs #9 and #11, tasking PR #10) got its `verify` run in state `action_required`: GitHub does not run workflows for events created by `GITHUB_TOKEN` without approval. dorfl's own "Version Packages" PR shows the same. The advance path passes `DORFL_GH_TOKEN` when set (a PAT makes the PR trigger CI normally), but `intake.yml` deliberately passes none (`ci-split-generate-workflows` Decisions), so intake PRs always need a manual approval. At least `docs/ci/README.md` should state this and recommend `DORFL_GH_TOKEN`; consider whether intake should pass it too.
