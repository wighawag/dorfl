title: 'The close-job closes a spec issue while some of the spec tasks are still staged in tasks/backlog'
slug: spec-complete-ignores-staged-backlog-tasks
date: 2026-09-29
status: spotted
---

Found in the CI sandbox `wighawag/dorfl-ci-sandbox` (private, dorfl `main@e972795d` installed from a tarball, workflows generated by `install-ci`), while exercising the split CI workflows end to end.

Issue #4 (a spec from intake) was closed with "every task of spec `text-layout-module-wrap-pad-and-align` has landed in `work/done/`" as soon as its first task merged, while `text-layout-pad` and `text-layout-compose` were still in `work/tasks/backlog/`. Cause: `isSpecComplete` (`spec-complete.ts`) scans only `TASK_LIFECYCLE_FOLDERS` (`tasks-ready`, `in-progress`, `done`), never `tasks-backlog`; tasking stages its tasks in backlog by default (`tasksLandIn: backlog`), so staged tasks are invisible and the spec reads complete once the promoted ones land. Pre-existing, not from the CI split. Fix: count staged tasks as not complete. Also decide how `tasks/cancelled` counts (a spec whose tasks are all cancelled should not close as "completed").
