---
title: 'install-ci neither sets nor checks the repository setting that lets GitHub Actions create pull requests'
slug: install-ci-does-not-enable-actions-pr-creation
date: 2026-09-29
status: spotted
---

Found in the CI sandbox `wighawag/dorfl-ci-sandbox` (private, dorfl `main@e972795d` installed from a tarball, workflows generated by `install-ci`), while exercising the split CI workflows end to end.

A new repository has "Allow GitHub Actions to create and approve pull requests" off (`gh api repos/<r>/actions/permissions/workflow` shows `can_approve_pull_request_reviews: false`). With it off, every propose-mode PR the generated workflows try to open with `GITHUB_TOKEN` is refused, so intake and propose builds silently open no PR (see `intake-reports-an-opened-pr-when-pr-creation-failed`). dorfl's own repository has it on, which is why this never showed there. `install-ci` should check it and either set it (it is an admin API, like the branch protection it already sets) or fail loudly with the exact command (`gh api -X PUT repos/<r>/actions/permissions/workflow -F can_approve_pull_request_reviews=true -f default_workflow_permissions=read`). The docs should say it is required.
