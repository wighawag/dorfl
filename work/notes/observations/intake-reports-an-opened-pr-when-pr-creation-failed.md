title: 'Intake reports that it opened a PR when the PR creation failed, and never shows the gh error'

status: spotted

Found in the CI sandbox `wighawag/dorfl-ci-sandbox` (private, dorfl `main@e972795d` installed from a tarball, workflows generated by `install-ci`), while exercising the split CI workflows end to end.

Issues #1 and #4: the apply job logged `the runner integrated it through the shared core and opened a PR carrying it (main untouched)`, but no PR existed (the repository did not allow Actions to create PRs). `GitHubProvider.openRequest` returned `opened: false` with an `instruction` holding the real `gh` error and a manual `gh pr create` command, but `intake.ts` builds its completion message from `core.outcome === 'completed'` only (around the `opened a PR carrying it` string) and never prints the instruction. The completion comment on the issue then has no PR link (issue #4), and nobody learns the PR is missing. Expected: when the request was not opened, say so in the log and the issue comment, and print the instruction. The build path may have the same gap; check `ci-phase-build.ts` apply and `complete`.
